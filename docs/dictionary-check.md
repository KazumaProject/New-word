# v1.7.262の照合

New-wordはconverterを変更せず、公開済みの`japanese_keyboard_dictionary_assets.zip`を読み取ります。固定したZIPのサイズ・SHA-256、全38パック（基本8・分類別30）の件数、全件の読み出し結果のSHA-256は`data/dictionary-release.json`に保存しています。Releaseの`latest`や別のメタデータ用snapshotは使用しません。

2026-10-15に旧固定Release `v1.7.256` のAPIが404を返すことを確認し、公開中の安定版 `v1.7.262` に固定先を更新しました。Release APIのサイズ・SHA-256と実際のZIPが一致することを確認し、全38パック・2,197,917件を読み出しました。New-wordの読み取り処理による全件出力のSHA-256は次のとおりです。

```
df2fe3c01576905ebb4b8c08571f2bef1ad496013308c0e8428cf15db81ff042
```

検証用の内部形式は、ファイル名順、読みトライの終端ノード順、各読みのtoken順に並べた`pack<TAB>base64(UTF-8 reading)<TAB>base64(UTF-8 conversion output)<LF>`です。配布TSVの形式には影響しません。全出力をこのハッシュで検証してから、共通のNFKC・空白・英字大小の正規化で索引へ登録します。索引は1実行内で共用し、再利用時にもSQLiteファイルのSHA-256・整合性・辞書情報を確認します。

`DecodeDictionary.java`はconverterのv1.7.262（commit `0fe61a4d2f384834d25112ab24f152a787e1ad6e`）の保存形式を読み取ります。同コミットのLOUDS・LOUDSWithTermId・TokenArrayの保存・読み出しコードを確認しました。実アプリ全体の変換動作を検証したものではありません。外部ライブラリ、converterのcheckout・ビルド・APIへの書き込みは必要ありません。

- `-2`のtokenは読みそのもの、`-1`は読みをカタカナにした変換出力として照合します。
- 読み補正パックは補足説明より前の表記を照合します。
- 各tokenを重複・漏れなく読み出せたこと、パックごとの件数、想定外の単語ファイルがないことを検証します。
- UTF-16コード単位の順序を保存し、隣接する絵文字も元の表記どおり復元します。
- 境界が64bitに一致する旧BitSetの最後の区切りも読み取ります。

照合の範囲は、辞書エントリの表記です。IME全体の変換結果や順位、カタカナ化、複数語を組み合わせた変換の可否は判定しません。表記が一致した語は読みが違っていても除外します。
